# EventFlow — Engineering Specification

This is the rulebook. Every Lambda, every Terraform module, every commit follows this, regardless of which session or which AI wrote it. When prompting Antigravity or any AI assistant for code, start the prompt with: "Follow the EventFlow Engineering Specification (docs/00-engineering-spec.md)."

## API conventions

- Base path: `/api/v1/...` — versioned from day one
- JSON field names: `camelCase`
- Success response: return the resource directly, HTTP 200/201
- Error response, always this shape:
```json
{ "success": false, "message": "Event is full", "errorCode": "EVENT_FULL" }
```
- Every request carries `X-Request-ID` (generated by API Gateway if not supplied by the caller) — this ID is logged end to end

## Logging

Structured JSON only, never plain strings. Minimum fields on every log line:
```json
{ "requestId": "...", "eventId": "...", "action": "register", "latencyMs": 42, "status": "success" }
```

## Naming conventions

- Python: `snake_case` for files/functions, PEP 8, type hints required on all function signatures
- Go: standard `gofmt`, package per responsibility (`checkin`, `validation`, `storage`)
- Terraform resources: `eventflow-{env}-{resource}` (e.g. `eventflow-dev-events-table`)
- DynamoDB attributes: `camelCase`

## Commit conventions

Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`. One logical change per commit.

## Branching

- `main` — protected, deploys to prod on merge
- `develop` — deploys to dev on push
- `feature/*` — PR into `develop`, requires passing CI

## Testing requirements

Every Lambda handler ships with:
- Unit tests (pytest + moto for Python, `go test` for Go) covering success and at least one failure path
- No PR merges without CI green

## Documentation requirements

Any new or changed endpoint updates `openapi.yaml` and `docs/04-api.md` in the same PR — the API contract never drifts from the code.
